# 系统评估报告

**问题**　给定同一批中文金融文档，更复杂的检索能否把完整证据排得更靠前？返回正确证据后，生成器能否选对引文并保持财务口径？本报告冻结四份原始 PDF，分别评价检索、单元格抽取、生成和成本。

## 样本与证据标准

| 文档 | PDF 页数 | 材料类型 | 主要混淆项 |
|---|---:|---|---|
| cmb-fy24 | 17 | 招商银行 2024 年年度报告摘要 | 年度、同比、净利润及归母口径 |
| cmb-q324 | 27 | 招商银行 2024 年第三季度报告（A 股） | 合并与本行、单季与累计、年化比率 |
| cmb-div | 3 | 2024 年年度 A 股分红派息实施公告 | 每股、A 股合计、全体股东合计 |
| cmb-note | 4 | 东莞证券 2024 年年报点评 | 公司披露、券商解释与预测 |

18 道检索题中，14 题要求一个证据组，4 题要求两个组。一个组可以含多个可替代 PDF 页。命中定义为前 K 个**证据块**中有一块来自指定文档和页。同页多块只为该组记一次。第一页编号为 1。标注针对指定出处，库中其他等价叙述若未列入会被记作未命中；页内无关段落也可能被记为命中。生成题另作逐段核查。[题目和标注](../bench/questions.json)

## 检索与分块

BM25 使用中文相邻双字、英文词和数字，k1=1.2、b=0.75。BGE-small-zh-v1.5 使用固定 ONNX 量化导出、CLS 向量、L2 归一化和余弦排序。混合检索分别取两路前 50，以 RRF 常数 60 融合。重排只改融合结果前 20 名，使用融合分与 42 词项窗口内的 IDF 覆盖度。这里的重排是可解释的启发式算法。

每种分块均保留 PDF 页边界。定长方案每块最多 380 字符；结构方案在标题、表行与句尾组织内容；语义方案另比较相邻单元 BGE 余弦，在缓冲区达到 80 字符且相似度低于 0.68 时切开。表格增强额外插入可解析的年度行及其表头。结构分块含 213 块，定长含 177 块，语义分块含 420 块，关闭结构方案的表格增强后有 201 块。分块大小和可检索单元数同时变化。

对每题计算命中组数除以所需组数，再对题取平均，得到 Recall@5。MRR@5 对第一个命中排名取倒数，未命中为零。完整命中率要求覆盖全部组。下面固定结构分块和表格增强。延迟取已建索引条件下每题一次检索的分位数，向量查询清空问题向量缓存；不含启动、建库和生成。

| 检索方式 | Recall@5 | MRR@5 | 完整命中 | p50 毫秒 |
|---|---:|---:|---:|---:|
| BM25 | 0.861 | 0.880 | 14/18 | 0.78 |
| BGE 向量 | 0.806 | 0.670 | 13/18 | 5.41 |
| RRF 混合 | 0.861 | 0.756 | 14/18 | 7.55 |
| 混合 + 重排 | 0.861 | 0.838 | 14/18 | 9.41 |

固定 BM25 和表格增强后，定长、结构、语义分块的 Recall@5 分别为 0.861、0.861、0.944。语义方案完整命中 16/18；r16 和 r18 仍各漏一个来源。对结构分块关闭年度表格增强，BM25 的两项排名指标均未变化。所有配置的 p95、完整命中和逐题排序均可复算。[全部指标](../results/metrics.json) · [逐题排名](../results/retrieval-traces.json)

## 金融抽取

整页转录年报摘要第 3 页的 15 个指标 × 3 个年度，共 45 个单元格。匹配键包含主体、指标、年度、单位和数值；文档与页预先固定。同比列不是第四个年度。两次运行使用同一个词典，比较仅用行文数值模式和额外使用年度表头/行列对齐。评估本页出现的全部 15 项，包含词典尚未覆盖的项目。

| 条件 | TP | FP | FN | Precision | Recall | F1 |
|---|---:|---:|---:|---:|---:|---:|
| 仅行文模式 | 0 | 0 | 45 | 未定义 | 0.00 | 0.00 |
| 启用表格行列解析 | 27 | 0 | 18 | 1.00 | 0.60 | 0.75 |

18 个漏项包括扣非归母净利润、基本及稀释每股收益、扣非基本每股收益、每股经营现金流及扣非加权平均 ROE 各三个年度。零误报仅针对这一页；行文模式无法从这张几乎全部由表格组成的页面生成带期间和单位的记录。它是很弱的对照。叙述候选（风险、事件、原因等）未作独立实体级 F1 评价。[逐格参考值](../bench/extraction.json)

## 两种本地模型的问答实验

同一套结构分块、混合检索、top-4、同一系统提示、温度 0、最多输出 350 token。6 题包括 5 道可答题和 1 道材料不足题。模型逐论断选一个证据段，程序回填该段。生成器收到相同的输入，共 6,431 个 prompt token/模型。公开轨迹记录回答、页码、块号及所选片段的 SHA-256；本地复跑还会生成包含片段的完整记录。

| 采用 Q4_K_M 权重 | 正确题数（共 6） | 可答题正确 | 材料不足题正确拒答 | 忠实论断 / 输出论断 | 引文支持 / 输出论断 | 端到端 p50 | 输出 token |
|---|---:|---:|---:|---:|---:|---:|---:|
| Qwen2.5-0.5B-Instruct | 1 | 1/5 | 0/1 | 1/5 | 0/5 | 6.19 秒 | 441 |
| Qwen2.5-1.5B-Instruct | 3 | 3/5 | 0/1 | 3/6 | 1/6 | 7.65 秒 | 121 |

一次离线对照中的全部模型请求由本机 llama.cpp CPU 服务实际执行。两次运行的直接 API 账单均为 0 美元。没有测量电耗、硬件摊销、人工复核或云服务价格。部分进程运行时间重叠，延迟用于描述这次运行，不能据此给两个模型做速度排名。

**判分。** 正确性要求问题所需全部期间、口径、单位和数值匹配；当问题已给出单位时，单独给对数值可记正确。Faithfulness 要求答案在题意下得到全部检索上下文支持；Citation Accuracy 进一步要求模型选择的那段证据足以支持答案。无可展示输出的题记答错，不计入输出论断分母。材料不足题期待明确表达材料不足；只说“否”并援引无关文字记错。标签为本项目对照原文的一次评阅，尚无第二名独立评阅者。[逐题判分和理由](../bench/review.json) · [小模型轨迹](../results/qwen05.json) · [较大模型轨迹](../results/qwen15.json)

**可定位的失败。** a01 问每股含税金额，1.5B 回答了 412.58 亿元，这是公告中 A 股派息合计。a02 回答 25 户正确，但选择了页眉。a03 答出 92 天，却选择了注释标记。a06 将集团和归母口径混入同一序列。数字匹配检查只能提示引文中是否出现所报数字，无法识别每股与合计的混淆。年度序列功能直接从表格列对齐计算，可独立核对 a06。

## 复现

1. 按 README 安装，执行 `python -m finrag demo` 及 `python -m scripts.fetch_encoder`。
2. 执行 `python -m bench.evaluate --output data/local/reproduction`。将结果与已发布 JSON 的非计时字段比较。
3. 取得 [llama.cpp b12780](https://github.com/ggml-org/llama.cpp/releases/tag/b12780) 对应平台的 CPU 版本。运行 `python -m scripts.fetch_llm 0.5` 或 `python -m scripts.fetch_llm 1.5`；脚本校验 GGUF 的完整哈希。依 README 分别启动服务，模型别名用 qwen05、qwen15，线程数 5，上下文 4096，单并发。
4. 分别设置服务地址、模型别名、本地零费率，再执行 `python -m bench.generate data/local/replay05.json` 或 `python -m bench.generate data/local/replay15.json`。在同一份题集上对新生成的引文重新评阅。输出目录需存在。
5. `python -m bench.score_answers` 复核已发表的标签、分母与记录哈希。新模型输出即使答案文字相同，时延等字段也会变动，需为新试验单独保留标签与轨迹。
